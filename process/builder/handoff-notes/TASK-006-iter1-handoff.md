## Implementation Details

### Transaction pattern

```javascript
return sequelize.transaction(async (transaction) => {
  await sequelize.query('SET LOCAL app.current_user_id = :userId', {
    replacements: { userId },
    transaction,
  });

  const note = await Note.create({ ... }, { transaction });

  await NoteVersion.create({
    note_id: note.id,
    title: note.title,
    body: note.body,
    version_number: 1,
  }, { transaction });

  return note;
});
```

`SET LOCAL app.current_user_id` is executed as the first statement inside the transaction so RLS policies see the correct user for both the `notes` and `note_versions` inserts.

### Folder validation

Folder ownership is checked before opening the transaction. `Folder.scope({ method: ['forUser', userId] })` scopes the lookup to the requesting user, so a folderId that exists but belongs to another user returns null and triggers `FOLDER_NOT_FOUND`. The route translates this to HTTP 404 (`{ error: 'Not found' }`), consistent with the ownership guard pattern used elsewhere (prevents resource enumeration).

### Route error handling

The route handler catches `FOLDER_NOT_FOUND` explicitly and returns 404. All other errors are forwarded to `next(err)` for the application-level error handler to process.
